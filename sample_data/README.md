# Sample datasets

Demo data for the platform: three realistic training datasets plus "new data" batches
that show drift monitoring working. All files are generated by
[`generate_samples.py`](generate_samples.py) with a fixed random seed. Run
`python sample_data/generate_samples.py` to recreate them.

The batch files have **no target column**, the same as real data arriving after deployment.

## 1. Customer churn (classification)

Predict whether a telecom customer will leave (`churned` = Yes / No).

| File | Rows | What it is | Drift result |
|---|---|---|---|
| `customer_churn_train.csv` | 2000 | Training data, about 30% churn | — |
| `churn_batch1_normal_month.csv` | 500 | A normal month, same customers as training | **Stable** |
| `churn_batch2_price_increase.csv` | 500 | Company raised prices 25% | **Drift in `monthly_charges` only** |
| `churn_batch3_major_shift.csv` | 500 | Sign-up campaign: many brand-new customers, a new **UPI** payment option, more support tickets, and a billing bug that left 20% of charges blank | **Drift in `payment_method`, `tenure_months`, `support_tickets`**; the jump in missing values is also shown |

Columns: `age`, `tenure_months`, `monthly_charges`, `contract_type`, `internet_service`,
`payment_method`, `tech_support`, `support_tickets`, `churned`.

Churn is more likely with month-to-month contracts, short tenure, high charges,
fiber internet, electronic-check payments, many support tickets and no tech support.
SHAP should rank the contract type and tenure near the top.

## 2. House prices (regression)

Predict a house's price in lakhs (`price_lakhs`; 1 lakh = ₹1,00,000).

| File | Rows | What it is | Drift result |
|---|---|---|---|
| `house_prices_train.csv` | 1500 | Training data, prices about 12 to 230 lakhs | — |
| `house_batch1_normal.csv` | 400 | Same market as training | **Stable** |
| `house_batch2_new_township.csv` | 400 | A new township far from the city with larger, newer homes | **Drift in `location` (new category), `area_sqft`, `house_age_years`, `distance_to_city_km`** |

Columns: `area_sqft`, `bedrooms`, `bathrooms`, `house_age_years`, `distance_to_city_km`,
`location`, `condition`, `has_parking`, `price_lakhs`.

## 3. Student performance (classification)

Predict whether a student passes (`result` = Pass / Fail).

| File | Rows | What it is | Drift result |
|---|---|---|---|
| `student_performance_train.csv` | 1800 | Training data, about 62% pass | — |
| `student_batch1_normal_semester.csv` | 450 | An ordinary semester | **Stable** |
| `student_batch2_online_semester.csv` | 450 | The semester moved online: a new **Online** class mode, lower attendance, less study time, fewer assignments handed in | **Drift in `class_mode`, `assignments_submitted`, `attendance_pct`, `study_hours_per_week`**; sleep, past scores and the rest stay stable |

Columns: `study_hours_per_week`, `attendance_pct`, `previous_exam_score`,
`assignments_submitted`, `sleep_hours`, `class_mode`, `extracurricular`,
`parent_education`, `result`.

Passing depends mostly on past scores, study hours, attendance and assignments.
SHAP ranks these four at the top. In the test run the best model reached about
74% accuracy (F1 about 0.81).

## Demo script (about 5 minutes)

1. **Datasets** → upload `customer_churn_train.csv` → set the target to `churned`.
   The app detects that this is a *classification* task.
2. **Experiments** → create an experiment on it with *Tune hyperparameters* ticked.
   Training takes about 20 seconds.
3. Open the experiment and walk through it:
   - **Metric comparison:** expect accuracy around 0.79 and AUC around 0.82.
   - **Best model:** the **Best** badge marks the model with the highest F1.
   - **SHAP:** click **Explain (SHAP)** to show which features drive churn.
   - Click **Deploy** on the best model.
4. **Drift** → select the deployed model and upload the batches in order:
   1. `churn_batch1_normal_month.csv` → *No significant drift*.
   2. `churn_batch2_price_increase.csv` → drift flagged on `monthly_charges` only.
      Click it to show the training-vs-new comparison.
   3. `churn_batch3_major_shift.csv` → several features drift. Point out the new
      "UPI" category, the shorter tenure, and the missing-values warning.
   The trend chart now shows the drift score climbing across the three checks.
5. Optionally, repeat with `house_prices_train.csv` (target `price_lakhs`). It is
   detected as *regression*, R² is about 0.94, and `house_batch2_new_township.csv`
   shows a new location category appearing.

## Notes

- The metrics above come from a test run, so treat them as approximate. The drift
  results depend only on the files, so they come out the same every time.
- Upload the batch files unchanged. The drift page's CSV reader expects plain
  comma-separated values without quoted fields, which is how these files are written.
